# Scalable Visualization of Massive 3D Datasets

This repository contains the source code, execution scripts, and performance analysis for a **Distributed 3D Stencil Computation and Isovalue Extraction** system. This project was developed as part of the CS633 (Parallel Computing) coursework and rigorously profiled on the **PARAM Rudra Supercomputer**.

## Overview

Processing large-scale 3D grid data presents heavy computational challenges. This project addresses these by manually partitioning a 3D grid across multiple parallel computational processes using **Domain Decomposition**. The system computes dynamic d-point stencil averages over multiple timesteps and detects crossing intersections using an edge-check (marching squares) approach. 

## Key Optimizations & Architecture

* **Strictly Non-Blocking Orchestration:** Boundary synchronization is executed using `MPI_Isend` and `MPI_Irecv` communications to prevent deadlocks and seamlessly hide network latency across parallel nodes. Up to 12 requests per field are issued before synchronizing with `MPI_Waitall`.
* **1D Array Flattening:** Instead of relying on complex `***data` pointers, the 3D grid (including halo padding) is flattened into a contiguous 1D memory block accessed via a macro `IDX(i, j, k)`. This ensures contiguous memory allocations and significantly improves CPU cache locality.
* **MPI Derived Datatypes:** Non-contiguous memory slices (such as Y and Z faces of the 3D grid) are exchanged without relying on slow, manual `for`-loops. Custom datatypes were constructed using `MPI_Type_indexed` to offload packing and unpacking logic directly to the MPI library.
* **Algorithmic Determinism:** The reduction strategy reliably explicitly double-counts shared boundary edges using a backward-looking halo check, ensuring the distributed isovalue counts remain perfectly identical across all execution topologies.

## Compilation & Execution

### 1. Compilation
The code is written in C and requires an MPI compiler (e.g., OpenMPI or Intel MPI). Load your MPI module and compile using:
```bash
mpicc src.c -o src -lm
```

### 2. Execution via SLURM
Execution is managed via SLURM batch scripts to enforce specific node and processor configurations. To submit a job to the scheduler, run:
```bash
sbatch run_P32.sh
sbatch run_P64.sh
sbatch run_P96.sh
```

*(Note: The scripts are pre-configured to run the `120x120x120` and `240x240x240` grid sizes for 5 iterations (`T=5`) across varying process counts.)*

## Performance & Results

The code was profiled extensively across 32, 48, 64, and 96 cores. 

* **Consistency:** The extremely narrow boxplots generated by `plot.py` prove highly consistent execution times across 5 separate runs, indicating that our non-blocking MPI exchanges did not suffer from random network spikes.
* **Scaling:** For the `240x240x240` grid, the application demonstrated expected sub-linear strong scaling behavior, successfully dropping execution time from 8.75 seconds (at P=32) down to **8.54 seconds (at P=96)**. 

To visualize the performance data yourself, run:
```bash
python plot.py
```
This will output `Plot.png` based on the provided CSV data.
